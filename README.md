# 北京二手房成交分析看板

这是一个支持本地运行和 GitHub Pages 公网访问的交互式看板，数据源为项目目录中的 `北京成交数据.xlsx`。

## 访问权限（Supabase）

### 管理员与限次兑换码（2026-09-18）

- 首页完成邮箱登录后，经服务端确认是超级管理员才显示“管理员后台”链接；在同一标签页进入 `admin.html`。管理员 UUID 写入云端私有 `super_admins`，不以客户端邮箱或 `user_metadata` 授权；本项目管理员不等于 Supabase 项目管理员。
- 管理员免兑换码、无限次查看所有小区的新旧成交明细。**市场比较/全市排行/热力图仍使用免费快照**；本次不是全市最新聚合的实现。
- 后台输入已验证的用户邮箱、权益天数、兑换截止天数、最多查看次数（默认 100，可填 200 等，或选不限）及订单编号。签发随机码并绑定接收账号，服务器仅保存哈希和发码人/订单审计字段。明文仅在当前管理员页面内存中展示，退出/离开后清除；同订单参数原样重试不会重复发码。不包含自动收款、找回明文码、订单财务系统。
- 有效期和次数同时约束。一次非试用小区完整新成交查询扣 1 次，不按成交行数/分页扣；重新打开算新查看，本页图表操作不扣。服务器成功返回即视为一次，不承诺网络断线或浏览器未显示时绝不扣。同请求 ID 在 10 分钟内重试不重复扣，只能读同一小区且仍须账号权益有效；到期后不能复用。已领取试用的小区及管理员不扣次数。旧不限次码保持兼容。
- 查询改用 `housing_view_community`，完整单小区原子返回并扣次；`housing_new_transactions` 旧分页接口拒绝限次码，避免绕过。已取得的数据仍可被保存，次数不是 DRM。
- 管理员页面不加载 Cloudflare/地图等第三方脚本，CSP 仅允许本站代码与指定 Supabase 请求；不携带服务端密钥。GitHub Pages 的页面外壳公开可下载，但普通用户只能看到拒绝访问提示且 RPC 强制拒绝发码。若要求 HTML 本身也返回 403，需要改用带网关鉴权的托管。
- 本地验证：`npm run test:permissions` 和 `npm run test:ui`；云端 SQL 用 `scripts/verify_admin.sql`，全部虚构账号/发码在事务结束回滚。管理员权限已写入指定真实账号，真实发码仍须本人登录操作。

策略为“未登录看全部旧数据 → 验证邮箱后免费选 2 个小区看最新数据 → 兑换 token 扩展小区权益”。免费旧数据截至 2025-08-31，查旧数据不扣额度。新成交保存在 Supabase 非公开数据库，不随本站发布；公开快照为 445,034 条。

- 全市/区级市场统计、排行、热力图仍截至 **2025-08-31**，**最新全市聚合未实现，也不属于当前售卖承诺**。小区试用仅开放所选小区的新成交列表与曲线。
- 默认所有小区的旧成交明细直接可看；不签发访客 Cookie，不自动扣试用额度。邮箱验证码登录后，经用户二次确认才占用一个名额；累计两个，按账号保存，而非按浏览器重置。
- `supabase/migrations/` 的三份迁移提供账号权限、目录搜索、私有新成交表、试用/兑换、管理员签发及限次查询 RPC。
- 新版兑换码只在云端存哈希、绑定账号、从首次兑换起计时，支持撤销；`scripts/manage_supabase_tokens.py` 是运营发码/撤销工具。
- 账号弹窗提供人工购买联系方式：微信搜索手机号 **15611710247**，添加时备注 **房价分析工具**；手机号和备注均支持复制。购买前确认价格、有效期和查看次数，并提供已验证的注册邮箱，收到激活码后在同一账号兑换。网站不自动收款、不代发微信消息。
- 新 UI 包括小区搜索首页、市场研究区、账号弹窗和可关闭的首次使用指南；邮箱登录使用 8 位验证码、10 分钟有效，登录会话只保留在当前标签页。

- `scripts/manage_tokens.py` 是旧本地原型工具，生成的码不能用于新版 Supabase，勿向用户出售。
- **纯静态前端不能强制鉴权**。本版 Pages 前端只携带免费旧数据，新增记录由 Supabase RPC 按账号权限返回；不是下载完整库后加模糊遮罩。公开旧数据、已获授权显示的结果仍可被保存，不能承诺绝对防复制。
- 验证范围：前端逻辑、SQL 权限和静态快照回归由自动化测试覆盖；浏览器检查不替代真实邮件投递、本人登录后的发码/兑换端到端验收或云端多连接压力测试。未完成的真实账号验收不能视为已通过。

本机授权：双击 `scripts/authorize_supabase.command`，在官方页面登录后将验证码输入自己的终端。该脚本不会上传数据或发布站点。

权限 SQL 本地测试：`npm ci --ignore-scripts && npm run test:permissions`。前端逻辑回归：`npm run test:ui`。静态版真实免费快照与 Worker 消息回归（先构建 `docs/`）：`npm run test:pages`。重建账号客户端：`npm run build:cloud`。权限和前端逻辑测试使用虚构数据；这些自动化测试不代替云端邮件/并发/浏览器实测。

## 功能

- 支持全量小区名称搜索。搜索不受排行榜最低成交量门槛影响，可直接查看某个小区的全部历史成交。
- 小区详情同时展示逐笔真实成交价格、滑动统计价格、每月实际成交套数及完整成交记录。
- 小区详情支持高德地图 POI 定位，可显示小区地址、经纬度和可缩放底图，并缓存已确认的位置。
- 以成交单价为主指标，支持中位数、平均数、P30、P60、最高价和最低价。
- 支持 3/6/12 个月或自定义长度的滑动窗口。
- 支持相邻窗口、同比窗口和自定义基准区间。
- 支持面积区间、区域、商圈、户型过滤。
- 动态计算区域和小区排行榜，并按两期成交量、合计成交量和有效月份数过滤。
- 排行榜将价格或结构指标、本期/基准期实际成交套数放在同一行，以横向条形和具体数值对照；支持 Top 5/10/20/50/100/200/500 及自定义 1–500，默认 Top 20。切换 Top K 只改变展示数量，不重复计算；少于 K 个合格对象时会说明样本门槛，不会补入不合格对象。
- 筛选计算时显示转圈、禁用重复提交并暂时淡化旧结果；完成后整体更新，失败则保留上次结果并提示重试。历史成交表按内容宽度紧凑排版；顶部突出邮箱注册和两个小区试用入口。
- 同时展示价格涨跌、相对北京表现、成交量变化、面积中位数变化、成交周期和议价率。
- 使用本地北京行政区 GeoJSON 绘制区级地图；下跌为绿色，上涨为红色，样本不足为灰色。

## 快速启动

双击 `启动看板.command`，或者在终端中执行：

```bash
./启动看板.command
```

第一次运行会从 Excel 构建本地 SQLite 缓存，通常需要几十秒。以后如果 Excel 没有变化，会直接使用缓存。

如果项目 `outputs/` 下存在 `北京成交数据_2018-2026地理增强完整版.csv.gz`，本地看板会优先使用这份增强数据；也可以通过 `BEIJING_HOUSE_SOURCE` 显式指定数据源。增强数据和生成的本地缓存均被 Git 忽略，不会自动进入 GitHub 仓库。

默认地址：<http://127.0.0.1:8876>

## 命令行

```bash
# 只构建或刷新缓存
python3 scripts/build_database.py

# 显式指定私有增强数据并重建
BEIJING_HOUSE_SOURCE="/绝对路径/北京成交数据_2018-2026地理增强完整版.csv.gz" \
python3 scripts/build_database.py --force

# 启动服务
python3 app.py

# 运行计算与接口测试
python3 -m unittest discover -s tests -v

# 构建 GitHub Pages 静态版（输出到 docs/）
python3 scripts/export_pages_site.py
```

## GitHub Pages 版本

### 访问统计（Cloudflare Web Analytics）

- 已接入用户提供的公开站点 token；它不是 Cloudflare 管理 API 密钥，也不是付费兑换码。`static/analytics.js` 随静态构建复制到 `docs/`。
- 仅在静态构建、HTTPS、`liyongzhi.xyz` 默认端口下的 `/beijing-housing-dashboard`、`/beijing-housing-dashboard/`、`/beijing-housing-dashboard/index.html` 加载官方 module beacon。localhost、局域网、预览域名、其他项目路径不统计。未来更换域名或路径必须同步修改白名单。
- 关闭 SPA 路由自动统计；基础统计不等于小区查询次数或去重人数。注册、试用、兑换的运营报表不在本次接入范围内。
- 加载器不读取表单、成交数据、鉴权状态或浏览器存储，不传入自定义业务事件。保留官方页面浏览与性能采集；该第三方脚本与其他页面脚本一样在页面上下文执行，这不是隔离沙箱，不能承诺第三方永远不变。官方说明与采集细节见 https://developers.cloudflare.com/web-analytics/data-metrics/data-origin-and-collection/ 和 https://developers.cloudflare.com/web-analytics/faq/ 。不要把邮箱、兑换码或私有成交数据编码到页面 URL、标题、元素 ID 或资源地址中。
- 尊重 `navigator.doNotTrack === '1'` 和 `navigator.globalPrivacyControl === true`；仅在加载时检查。统计是可选依赖，网络失败不阻塞页面，不做循环重试。页面底部提供访问统计说明。
- `npm run test:ui` 包含域名/路径/协议/本地环境隔离、隐私信号、重复加载与失败容错测试，不会请求 Cloudflare，不制造测试访问。自动化测试不等于 Cloudflare 后台已收到数据。
- 正式发布后在 Cloudflare → Web Analytics → `liyongzhi.xyz` 中查看，并按 Path 筛选本项目。检查官方脚本加载和上报请求，再核对后台出现真实访问；无需新增 DNS 记录。避免同时启用自动注入和手动脚本。统计只能从上线接入后开始，广告拦截、隐私选择和网络失败可能漏计。

`docs/` 是可部署的静态前端。浏览器下载免费历史 SQLite，通过 Web Worker 中的 SQLite/WASM 在本机完成旧数据筛选、滑动指标、排行和查询，避免大数据计算阻塞页面和加载动画；新数据查询和账号权限由 Supabase 后端处理。小区名称搜索也会请求云端目录，只返回名称/区/商圈，不返回受限成交价格。无需自行运维 Python 服务器。静态部署必须同时携带 `pages-client.js`、`pages-worker.js` 和 `vendor/`，通过 HTTP(S) 访问。

导出时只选择 2025-09-01 之前的记录构建新库，不采用“复制全量库再删除”的方式。公开元数据只从过滤后的快照计算；拒绝私有导出覆盖参数，生成后做完整性和日期检查，再替换产物。发布流程另运行 `scripts/check_public_release.py`。这些检查不代替 Git 历史审计或云端权限测试。

导出时为 HTML 引用的 JS/CSS 及 Worker 依赖链生成内容版本号。元数据每次从网络读取，免费数据库使用内容哈希作为缓存版本，并核对行数和末日，避免旧浏览器缓存把不同版本的数据与界面混用。

- 实际行数、小区数和日期范围以构建后的 `docs/data/meta.json` 为准。
- 支持与本地版一致的动态统计口径和样本门槛。
- 高德地图密钥不会提交到仓库；如需小区 POI 定位，可在页面中填写自己的 Web Key 和安全密钥，它们只保存在当前浏览器。
- 精简数据库由源 SQLite 生成，不修改原始 Excel。运行 `python3 scripts/export_pages_site.py` 可重新构建。

可以通过环境变量修改监听地址和端口：

```bash
BEIJING_HOUSE_HOST=127.0.0.1 BEIJING_HOUSE_PORT=9000 python3 app.py
```

## 高德地图配置

推荐在高德开放平台创建“Web端（JS API）”应用，取得 Web Key 和安全密钥，然后在启动前设置：

```bash
AMAP_JS_KEY="你的 Web 端 Key" \
AMAP_SECURITY_CODE="你的安全密钥" \
python3 app.py
```

也可以在项目内创建不会被 Git 跟踪的 `config/amap.local.json`：

```json
{
  "amap_js_key": "你的 Web 端 Key",
  "amap_security_code": "你的安全密钥"
}
```

环境变量优先于本地配置文件。这两种方式都会由本地 Python 服务代理高德服务请求，页面中只会获得公开的 Web Key，不会包含安全密钥。也可以点击小区详情中的“地图设置”，将 Key 和安全密钥只保存在当前浏览器；该方式适合纯本地使用，不适合部署到公网。

定位时默认搜索“北京市 + 区 + 商圈 + 小区名”。如果高德返回的地点存在歧义，可以修改地图上方的搜索词并重新定位。成功结果会缓存在当前浏览器中，后续打开同一小区无需重复搜索。

### 小区坐标缓存与额度

- 热力图和详情共用按“区 + 商圈 + 小区”保存的坐标，不按时间窗口保存；切换日期/指标只重算价格与颜色。
- 已成功定位的坐标长期复用。页面先读取一次共享坐标库，再合并浏览器缓存；相同小区的并发查询合并，支持 Web Locks 的浏览器还会合并同源多标签页查询。
- 没有可靠匹配的结果缓存 7 天；高德错误/超时冷却 15 分钟并暂停本页批量补全，刷新同浏览器也会保留暂停状态。手动“重新定位”可绕过冷却；失败不会覆盖已有有效坐标。
- 仅绑定回环地址的本地服务允许本机同源请求将坐标写回 `data/community_locations.local.json`，不依赖付费账号。公开服务不会因此允许访客篡改共享坐标。
- 导出 Pages 时，从已有缓存抽取免费范围内小区的名称/地址/经纬度，写入 `docs/data/community-locations.json`；不包含价格、交易记录、付费独有小区或高德安全密钥。新浏览器也能复用这份快照。公开站新增浏览器定位结果暂不会自动回写 Supabase；运营方重新导出快照后才可共享。
- 地图底图/瓦片加载、缩放仍会访问高德，不等同于重复 POI 定位查询；实际计费与缓存使用期限需遵循高德账号对应的服务条款。本版未发起全城补点，避免一次消耗数千次额度。

## 数据口径

- 默认排除区域为 `-` 的记录、重复网页链接及明显异常记录。
- 默认有效范围：面积 10–500㎡、成交单价 3,000–200,000 元/㎡、成交总价 10–10,000 万元。
- 增强数据的免费快照覆盖至 2025-08-31，当前免费默认结束月份为 2025-08；新数据末日为 2026-08-29，不能将 2026 年 8 月称为完整自然月。若换回旧 Excel 数据源，默认月份以该次构建元数据为准。
- 地图边界来自 geojson.cn 的公开中国行政区划 GeoJSON 数据：`https://geojson.cn/api/china/1.6.2/110000.json`。
- 小区原始成交数据没有地址或经纬度。详情地图中的位置来自高德 POI 搜索结果，并显示匹配名称、地址和经纬度供核对；无法可靠匹配时会明确提示，不会用行政区中心点代替小区位置。

## 结果解释

排行榜是成交样本的统计结果，不等同于对房屋价值的估计。面积、户型、楼层、朝向、装修和楼龄结构变化都可能影响区间价格。看板会同时展示面积变化和样本量，建议优先比较同一区域、相近面积段且两期样本充足的结果。

排行榜门槛只用于市场横向比较。即使某个小区的近期成交量不足以进入排行，也仍然可以通过页面顶部的“小区搜索”查看它在数据中的全部历史成交。
